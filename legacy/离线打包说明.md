# 内网离线打包指南

如果在内网（无互联网连接）的机器上运行 `build-win-exe.bat` 失败，通常是因为 `pkg` 需要下载 Node.js 的底层二进制环境（如 `fetched-v18.5.0-win-x64`），但由于没有网络导致下载超时或失败。

要解决这个问题，只需两步即可完成离线打包配置：

## 1. 准备 node_modules

在**有网的电脑**上：
1. 下载或克隆本项目的完整代码。
2. 在项目根目录执行 `npm install`。
3. 将包含 `node_modules` 文件夹在内的整个项目拷贝到你的**内网机器**上。

## 2. 准备 pkg 离线缓存文件

`pkg` 依赖预编译好的 Node.js 二进制文件来进行打包。由于你的项目目标是 `node18-win-x64`，你需要提前下载对应文件。

在**有网的电脑**上：
1. 点击下载该文件：[uploaded-v2.6-node-v18.5.0-win-x64](https://github.com/vercel/pkg-fetch/releases/download/v3.4/uploaded-v2.6-node-v18.5.0-win-x64)
   *(注意：由于网络原因，可能需要使用加速器或代理)*
2. 下载完成后，将该文件**重命名**为：`fetched-v18.5.0-win-x64`

在**内网机器**上：
1. 在本项目的根目录下，创建一个名为 `.pkg-cache` 的文件夹。
2. 在 `.pkg-cache` 文件夹内，再创建一个名为 `v3.4` 的文件夹。
3. 将刚刚重命名好的 `fetched-v18.5.0-win-x64` 文件放入 `v3.4` 文件夹中。

你的目录结构应该像这样：
```text
你的项目目录/
  ├── .pkg-cache/
  │   └── v3.4/
  │       └── fetched-v18.5.0-win-x64    <-- 刚刚放进来的文件
  ├── node_modules/
  ├── public/
  ├── src/
  ├── server.js
  └── build-win-exe.bat
```

## 3. 开始打包

现在双击运行 `build-win-exe.bat`。脚本会自动检测到离线缓存并进行打包，最终会在 `dist/` 目录下生成 `intranet-chat.exe`。

---

## 常见问题排查

- **Q: 提示 `Error! Not able to build for 'node18-win-x64' ...`**
  A: 说明离线缓存文件放错了位置或名字不对。请严格检查文件路径是否为 `.pkg-cache\v3.4\fetched-v18.5.0-win-x64`，且文件没有后缀名（如 `.exe`）。
  
- **Q: 运行 exe 报错，提示缺少模块 (Cannot find module ...)**
  A: 极小概率发生。通常是因为代码中使用了动态的 `require(变量)` 导致打包工具未能识别。本项目已全部采用静态引用，不应出现此问题。如果遇到，请检查是否在拷贝代码时遗漏了文件。
